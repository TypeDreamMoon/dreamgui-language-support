# DreamUI Language Support

[English](README.md) | 简体中文

DreamGUI `.dui` 界面层级的语言支持。

## 功能

- **全语法高亮 + 语义身份着色**:绑定表达式(`Enabled <- !IsBusy() && Count() > 0`)、双向箭头
  (`Value <-> Volume`)、`use "…"` 导入与循环来源的两种形状都在语法高亮里;语义层按身份着色——
  节点 id 按"它将成为的成员变量"、样式按类、资源按只读常量、`->` 事件与处理函数、调用按函数、
  裸名字按变量、`each` 体内的 `Item.Member` 首段按它引用的循环参数、组件各归其位。
- **组件语法的高亮**:`use "Row.dui" as Row`、`use /Game/UI/WBP_Row as Row` 与
  `use "Lib.dui" as nier`;带类型词的 `props { … }` 与 `events { … }`;`OnClick -> emit Picked(Index)`;
  `slot Rows default : RowList { … }` 与宿主里的 `slot Detail { … }`;容器作节点类型
  (`VerticalBox Column { Spacing = 29 }`)与不写 id 的节点(`HorizontalBox { … }`、`Text : Caption { … }`);
  `@slot { A = 1  B = 2 }`、`@fill` 与 `@fill 2`;带命名空间的名字(`nier.Row`、`: nier.Label`、`@nier.Ink`);
  `if … else if … else`;`for Item in GetItems() { … }`;以及 `timeline` 块。一行写完的块
  (`+ UIButton { TransitionType = None  bCanNavigateHere = false }`、`Label = "MAP"; Icon = @IconMap`)
  里每条语句各按属性着色。
- **组件语法的代码片段**:组件文件(`dui-component`)、`props`、`events`、`emit`、`use-as`、`use-class`、
  `for`、`if` / `ifelse`、`slot-default`、`slot-fill`、`slotblock`、`shown`、`vbox`、`hbox`,与原有片段并列。
- **按上下文补全**:内建 tag、布局容器、组件类、逐类属性、枚举值、槽属性、资源类型、`@` 资源引用、`->` 事件名;
  数据来自插件导出的 `.dui-symbols.json` —— 补全提供的恰是编译器接受的,单一清单不漂移。组件语法同样有补全:
  文件可用作节点类型的别名(自己的 `use … as` 与库转出的)、`ns.` 命名空间、`props { }` / `events { }` 里的类型词、
  `->` 之后的 `emit` 与本文件的事件、`@` 之后的 `slot` / `fill` / `key`、只在合法位置出现的关键字,以及组件实例上
  它的 props、events 与插槽;容器类型的节点也补全容器的属性,`Shown` 是每个控件都有的属性。
  旧版插件导出的符号文件会按内置清单自动补齐容器、`Shown` 与类型词。
- **颜色芯片与取色器**:每个 `#hex` 字面量都有色块;取色器保持你的位数风格(`#F00` 保持短形式),
  且永不改写 `@` 引用。
- **hover 带 UPROPERTY 说明与类默认值**(默认值按语言自己的拼法打印,可直接粘贴);组件语法的 hover:别名解析到的
  文件与类及其 props / events / 插槽、命名空间名字的来源、`emit` 的签名、prop 的类型与默认值、匿名节点编译后的 id。
  大纲含 `if` / `else` 分支、按类型显示的匿名节点、插槽声明与填充、循环、`props` 与 `events`;
  token 级折叠与逐级扩选。
- **诊断用编译器的码与原文**:词法码 DUI1001–1006、单文件可判的结构码(含 DUI2013 嵌套上限),
  severity 与编译器一致;编译器仍是权威 —— 它可能接受的,这里至多是警告。每条码可点开中文解释;
  码表覆盖编译器的整张表,组件语法带来的码(`use … as`、`props`、`events`、`if`、槽、`for`、`emit`
  与两条新的写回拒绝)都在内,由测试守住。
- **workspace 导航**:Ctrl+T 搜全部 id/样式/资源;F12 按在嵌套 `/Game/X` tag 上落到声明它的文件,
  按在 `use "…"` 的拼写上打开被导入的文件(工作区里恰好一个文件匹配时才跳,宁可不跳不跳错);
  样式/资源/类路径的 find references。F12 也能从别名类型跳到组件文件、从 `use … as` 的名字跳到目标、
  从 `emit Picked` 跳到 `events` 条目、从绑定读的 prop 跳到 `props` 条目、从 `ns.Label` / `@ns.Ink` 跳到库里的声明、
  从插槽填充跳到组件的插槽。
- **会说这门语言的改名(F2)**:改节点 id 会**自动写 `(was: 旧Id)`**,下次编译迁移图引用、绑定与动画;
  改回旧名则删除子句。本地化 key 变化会提醒,并给出 `@key` 钉住旧 key 的写法。给匿名节点改名会在类型后写上 id
  (不写 `(was:)`,与插件的写回一致);别名与命名空间改名会改掉本文件里的每处使用,prop 改名连同读它的绑定,
  event 改名连同每个 `emit`。
- **提取与内联**:字面量提取为 `@资源`(单处或全部同值);选中属性行提取为样式(匿名节点也行,`if` 与循环体内拒绝);
  穿着的样式按基先派后展开回节点,样式里的 `+` 组件与槽属性一并带回。未知组件类型(DUI3003)在工作区里恰好有一个
  同名组件文件时,快速修复会补上 `use "…" as X`。
- **编译器诊断实时送达**:Unreal 编辑器开着时,每次编译 text-backed 类都会把裁决写进
  `DUI/.dui-diagnostics.json`,以 `dui-compiler` 来源出现在问题面板 —— 语义层(未知属性、坏值、
  缺失的绑定函数)与语法层并排,而扩展自己不长第二个编译器。
- **桥接 Unreal 编辑器**:`<-` / `->` 补全向活编辑器询问该类真正声明的函数;打 `/` 补全全部可嵌套的
  widget 类(编辑器在线走资产注册表,离线走 workspace 的 class 行);
  **Reveal in Unreal Designer** 打开设计器并选中光标所在节点;**Compile This File** 立即编译,
  裁决落在问题面板。
- **绑定表达式里的语义**:调用处有签名帮助(`(` 与 `,` 触发),函数与变量的 hover 给类型,
  `<->` 右侧补全列出该类的变量(带 FieldNotify 的排前,其余是每帧轮询),`each` 体内 `Item.`
  按数据源的元素类型补全成员。
- **格式化文档**(并作为 `[dui]` 的默认格式化器):按块深度缩进、`=` 与箭头两侧单空格、`}` 独占
  一行、空行折叠到一行 —— 与设计器写回的打印器同一套拼法,两个工具不会互相打架;结果重新分词,
  任何会改动 token 的格式化都被拒绝。
- **补 `use`**:样式或资源只在工作区另一个文件里声明时,quickfix 直接插入导入语句,拼法跟随文件
  里已有的 `use`。
- **包路径可点**:tag 或字符串里的 `/Game/...` 在活编辑器的内容浏览器里定位并打开(指向另一个
  .dui 的 tag 仍走 F12 跳到那个文件)。
- **从 Unreal 设计器 Reveal 到 VS Code**:工具栏与层级右键菜单一键跳到节点所在行;单独打开一个
  `.dui` 也会连同它所在的 `DUI/` 树一起索引,不开文件夹导入也能解析。
- **新文件命令**:与 Unreal 编辑器"Create Source File..."逐字节同款的 starter ——
  一个 root 加一个居中标签,用"出现了"回答"这一步成功了吗"。

## 这门语言刻意没有的东西

下面这些常被问到,每一项都是决定而不是缺口:扩展不会补全它们,编译器在能解析的地方拒绝它们,
没人先决定它们该是什么意思之前,也不会有。

`if` 和 `for` 曾经排在这张表的最前面。现在两者都进了语言,形状由语言的其余部分决定:`if` 切换可见性,
`for` 按类的数据重复一个模板。它们没有带来的,在下面。

| 语言里没有 | 为什么,以及该怎么写 |
|---|---|
| `#ifdef`、编译期条件 | `if` 是运行时开关而不是编译期开关:每个分支都会被建出来,分支里的 widget 各带一条"这个分支被选中"的 `Shown` 绑定,隐藏的分支是折叠而不是销毁,状态保留。文件里没有任何写法能把一个 widget 从类里拿掉;根本不该存在的变体是另一个类。 |
| 宏、文本模板 | 复用的单位是**组件**——带 `props`、`events` 和 `slot` 的 `.dui`,用它的 `use … as` 名字放置——或者**样式**,样式除了值还能带 `+ 组件` 块和槽行。两者都不是文本替换:实例是一个类,样式是一组行,都按名字解析。 |
| 变量、主题变量 | `resources { … }` 是具名常量的机制,经 `use` 解析(`use … as` 时在命名空间下),一份调色板放在一个文件里,每个界面导入它。`props` 是组件的输入——宿主设置或绑定的蓝图变量——不是文件自己重新赋值的值。自由变量多出来的只有*重新赋值*,那又回到了声明式的规则。 |
| 媒体查询、伪状态(`:hover`) | 状态总得由什么来驱动,在这个框架里那是行为(`UUISelectable` 一族已经管着悬停、按下、禁用和它们的过渡)。语言里再长一个状态机,就得逐帧和它对齐。 |
| 标志枚举的 `A \| B` | 语法里没有 `\|`,加运算符是改语言。组合写成**各标志相加的那个数**——编译器按枚举校验(`IsValidEnumValueOrBitfield`),写回也按数字印回来,来回是完整的。 |
| `a ? b : c`、`a / b`、`Items[0]` | 表达式语言是不含除法的算术(`/` 属于路径和注释)、比较、逻辑与调用,因为每加一个运算符,都要降成蓝图图、教给本扩展的扫描器、在三处写文档。选择或除法是类上的函数;下标是接一个参数的函数。对 widget 而言,选择就是 `if`。 |
| 数组与字典字面量 | 同一个理由,而且值没有地方落:语言能写到的属性没有一个从文本接收它们。`for` 或 `each` 重复的列表来自类——一个无参函数,或一个对象的 FieldNotify 数组。 |
| 字符串里的 `\uXXXX` | `.dui` 文件是 UTF-8,直接写那个字符。 |
| 嵌套循环、循环体里的表达式 | 一个模板只有一层重复:`for` 或 `each` 放进另一个循环里会被拒绝(DUI5021、DUI5012)。要嵌套,就用一个自己文件里带内层循环的组件。循环体里唯一的绑定是单跳的 `Item.Member`(DUI5014);更复杂的写到条目自己的类上。 |

## 智能从哪来

语义真相只有一份,在 C++ 编译器里。扩展的分工:

- **单文件字符能判定的**(词法、结构)—— 本地实时判,措辞照编译器逐字;
- **需要反射与类知识的**(属性、值、绑定)—— 由编译器经诊断信箱送达,或经桥实时询问;
- 两者都拿不到时,**明说降级**(状态栏),绝不猜。

## 构建

```
npm install
npm test            # tsc + node --test,不需要 VSCode 也不需要引擎
npm run build       # 打包到 out/extension.js
npm run package     # 产出 .vsix
```

设 `DREAMUI_CORPUS_DIR` 指向工程的 `DUI/` 目录,`npm test` 会把每个真实文件扫一遍,
词法与结构层必须零报。

## 发布

改 `package.json` 的 `version`,在 `CHANGELOG.md` 加上对应的 `## x.y.z` 一节,推到 `master`。
`release` 工作流会跑测试、打 `vx.y.z` tag,并发布带 `.vsix` 的 GitHub Release,说明取自那一节。
仓库里有 `VSCE_PAT` 密钥(`typedreammoon` 发布者的 Azure DevOps 令牌,Marketplace > Manage 权限)时,
同一个 `.vsix` 也会发布到 Marketplace;没有则跳过这一步。加上密钥后,手动运行一次工作流
(Actions > release > Run workflow)即可把已在 GitHub 发布的版本补发到 Marketplace。
